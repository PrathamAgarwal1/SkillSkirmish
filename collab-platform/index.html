SkillSkirmish

Intelligent Developer Matchmaking & Collaboration

"The primary objective of SkillSkirmish is to solve the problem of skill-based developer matchmaking by creating a system that dynamically assesses and tracks developer skills using AI-generated adaptive assessments and uses this data to enable intelligent collaborator discovery via Dynamic ELO & Vector matchmaking and powerful real-time IDE collaboration."

Problem Statement

Developers lack an intelligent platform that helps them discover suitable collaborators, evaluate their actual skill levels, and collaborate effectively in real time. Collaboration is often inefficient due to skill mismatch, unverified abilities, and fragmented tooling.

Collaboration Discovery Gap

No reliable way to identify collaborators with matching, verified skill levels. Developers don't know who to team up with.

Skill Verification Gap

Most platforms rely on self-claimed skills. No dynamic system to measure real ability through performance.

Platform Fragmentation

Discord/Zoom for calls, LeetCode for skills, LinkedIn for profiles — no single platform integrates assessment + matchmaking + collaboration.

Research Gap / Innovation

No existing platform combines all three pillars: verified skill assessment, intelligent matchmaking, and an integrated collaborative IDE into a single unified environment.

SkillSkirmish bridges this gap by using AI-generated adaptive questions and a CS2-inspired Dynamic ELO rating system that dynamically tracks developer skills and powers intelligent collaborator discovery.

Multi-Tier ELO Engine

The Core Probability Math

Our platform utilizes an incredibly customized Multi-Tier ELO Model to evaluate AI-generated quizzes. The algorithm predicts success probabilities based on the difference between the developer's rating ($R_U$) and the active AI question's strict difficulty ELO ($R_Q$).

Infinite Scaling

Dynamic Targeted Quizzes (No Question Banks!)

SkillSkirmish has zero static questions. When you begin an assessment, the backend instantly queries the DB for your exact current ELO in that specific skillset (e.g., $1650$ React ELO). The algorithm forcefully injects this mathematical parameter ($R_U = 1650$) directly into the Generative AI Pipeline (Groq/Gemini), instructing it to dynamically synthesize a completely unique problem precisely matched to your rating. If you fail, your ELO drops and the AI strictly constructs easier challenges on the next iteration. If you win, the AI ramps up the prompt difficulty exponentially!

1. Expected Probability ($E$)

When a developer is assigned an AI interview question, the engine mathematically maps their odds of answering correctly:

$$ E = \frac{1}{1 + 10^{\frac{R_Q - R_U}{400}}} $$

2. Dynamic K-Factor Scaling ($K$)

Your resulting ELO shift heavily modifies itself using Tiered $K$-Factors based purely on your recorded matches over time. This mimics CS2-style trust bounds:

  • $K=40$: Provisional ($<30$ matches)
  • $K=20$: Established Default
  • $K=10$: Elite Optimization ($\ge 2400$ ELO)

Live Math Calculation: Provisional vs Elite

Let's plot exact numerical calculations showing how our backend evaluates standard answers.

Case 1: Rookie Upsets Expert AI

  • State ($R_U$): $1500$ ELO ($K=40$).
  • AI Target ($R_Q$): Hard Quiz ($1800$ ELO).
  • Outcome: User Correct ($Actual = 1.0$).
// Algorithm Prediction: 15% E = 1 / (1 + 10^((1800 - 1500) / 400)) ≈ 0.150
ΔRating = 40 × (1.0 - 0.150)
Massive Gain: +34.0 ELO Points!

Case 2: Rookie Fails Basic Quiz

  • State ($R_U$): $1500$ ELO ($K=40$).
  • AI Target ($R_Q$): Easy Quiz ($1200$ ELO).
  • Outcome: User Incorrect ($Actual = 0.0$).
// Algorithm Prediction: 84.9% E = 1 / (1 + 10^((1200 - 1500) / 400)) ≈ 0.849
ΔRating = 40 × (0.0 - 0.849)
Massive Drop: -33.9 ELO Points!

Case 3: Elite Grinds Easy Quizzes

  • State ($R_U$): $2450$ ELO ($K=10$).
  • AI Target ($R_Q$): Easy Quiz ($1200$ ELO).
  • Outcome: User Correct ($Actual = 1.0$).
// Algorithm Prediction: 99.9% E = 1 / (1 + 10^((1200 - 2450) / 400)) ≈ 0.999
ΔRating = 10 × (1.0 - 0.999)
Anti-Farming Cap: +0.01 ELO Gained.
Severe!

Case 4: Elite Hubris Penalty

  • State ($R_U$): $2450$ ELO ($K=10$).
  • AI Target ($R_Q$): Medium Quiz ($1500$ ELO).
  • Outcome: User Incorrect ($Actual = 0.0$).
// Algorithm Prediction: 99.6% E = 1 / (1 + 10^((1500 - 2450) / 400)) ≈ 0.996
ΔRating = 10 × (0.0 - 0.996)
Catastrophic Penalty: -9.96 ELO Lost!

Bi-Directional Matchmaking Algorithms

SkillSkirmish employs a Two-Way Matchmaking System. Searching does not only pair individuals together. Users can trigger a Peer Discovery Vector to find optimal collaborators, OR a Room Discovery Vector to find active environments mathematically compatible with their skill profiles.

Vector A: Peer Discovery (User-to-User)

1. Vector Cosine Similarity

Users' technical skillsets are computationally mapped as Vector arrays. The engine mathematically calculates the Cosine Similarity and amplifies it via a Non-Linear Power ($1.5$) to exponentially favor highly-identical tech stacks over weak overlaps.

2. Trust Factor Penalties

Systemic smurf suppression via competitive gaming mechanics. Users with $< 20$ assessed matches suffer up to a $90\%$ algorithmic penalty (`rdPenalty`), strictly preventing unverified accounts from disrupting Elite queries.

The Gaussian "Growth" Curve

Instead of perfectly mirroring rating scores, our algorithm uniquely utilizes a Normal Distribution (Gaussian Curve) to aggressively hunt for opponents statistically centered precisely +75 ELO points higher to enforce optimal mentor pairings.

$$ Growth\_Bonus = \exp\left(-\frac{(Gap - 75)^2}{2 \times 50^2}\right) \times 10 $$

Vector B: Room Discovery (User-to-Environment)

Rooms contain their own strict aggregated criteria schemas. High-end collaborative rooms perform algorithmic compatibility checks against individual searchers by parsing active Room skill presence vs. User vectors.

1. Aggregate Floor Penalties

Rooms declare minimum ELO floor constraints. Users falling mathematically beneath the aggregate room boundary undergo aggressive decay equations, filtering them out of high-tier environments.

2. Presence Vector Scoring

Instead of deep Cosine Vectors, environment matching uses Binary Presence Strings. It checks required vs. active abilities for lightning-fast database filtering at scale.

3. Capacity Headroom

Room matchmaking heavily boosts groups with active users that are approaching, but haven't hit, capacity constraints, artificially concentrating density into active lobbies.

System Architecture

SkillSkirmish is powered by a high-performance Express/Node.js backend. To handle real-time vector matchmaking and dynamic LLM prompting, our Mongoose Database Schemas and REST APIs are structurally optimized for rapid, high-throughput scaling.

Mongoose Datastore

User.js Schema

Embeds isolated ELO ratings per technology inside a sub-document array instead of flat columns.

skills: [{
  name: String,
  elo: { type: Number, default: 1200 },
  matchesPlayed: Number,
  isProvisional: Boolean
}]

Room.js Schema

Defines live cluster capacities and mathematical limits to natively filter candidates via DB queries.

requiredSkills: [{ name: String, weight: Number }],
minRating: { type: Number, default: 0 },
capacity: { type: Number, default: 10 },
activeCalls: [VideoCallSchema]

AssessmentSession.js Schema

Tracks AI-generated payloads in isolated document sessions, storing Expected Probability math metrics safely.

currentDifficulty: { type: String, enum: ['Easy', 'Medium', 'Hard'] },
questionsLog: [{ questionText: String, difficultyElo: Number, scorePercentage: Number }],
finalResult: { accuracy: Number, ratingChange: Number }

Express REST Network

POST

/api/assessment/generate

Extracts $R_U$ from `req.user.skills`, connects via `Groq SDK` generating dynamic logic, returning JSON difficulty payload.

Req -> verifyJwt -> DB(User) -> GroqAPI -> JSON

POST

/api/matchmaking/find-match

Constructs Required Skillset Matrix, pulls Candidate Matrices out of MongoDB, executes `computeMatchScore()` math, returns ranked Array.

PATCH

/api/rooms/{id}/join

Fires transaction validating compatibility floor / capacity constraints. Emits WebSocket broadcast triggering WebRTC UI layout refresh across peers.

Real-Time Transport Layer

Socket.io (Signaling) Mediasoup (WebRTC SFU)

Code Execution Sandbox

server/routes/execute.js

Spawns isolated `child_process` threads to safely execute and stream output from Collaborative IDE code.

// Stream standard output back to WebSockets

API Endpoints

Assessment API — AI-Powered

POST/api/assessment/start

Purpose: Start a new assessment session. Generates the first AI question.

Input: { skill } · Output: { question, options, type, difficulty, codeTemplate, testCases }

Internal: Builds question plan (8 coding, 6 MCQ, 6 subjective), calls AI model to generate first question, creates AssessmentSession in DB.

POST/api/assessment/submit

Purpose: Grade user answer and generate next AI question.

Input: { userAnswer } · Output: { scorePercentage, feedback, correctAnswer, nextQuestion }

Internal: MCQ: exact match. Subjective/Coding: AI evaluation via evaluateSubjectiveWithAI(). Logs result, generates next question from AI.

POST/api/assessment/finish

Purpose: Calculate final rating changes from all answers and update user skill rating.

Input: None (uses session) · Output: { accuracy, oldRating, newRating, ratingChange }

Internal: Calculates rating change using probability formula, updates User.skills in MongoDB.

POST/api/assessment/skip

Purpose: Skip current question, generate next AI question without grading.

Matchmaking

Input: { requiredSkills, targetRating }

Database Schemas

User Schema

Stores user accounts, profile info, skills with ELO rating, assessment history, and social links.

Tracks active quiz sessions: AI-generated questions, answers, plans, and final rating result.

Stores collaboration rooms with members, video call channels, and room settings.
